# PROCESIO CLI + Agent

Instructions for an AI assistant working in this repository. A human reader wants
[README.md](README.md) instead.

Command-line tooling and an AI agent for the PROCESIO automation platform: drive processes, forms, documents and custom actions from a terminal or from an AI coding assistant.

## What this repo is

A registry of **tools** and **agents** for the PROCESIO automation platform. A tool is
a script that talks to PROCESIO. An agent carries method rather than mechanics: it
drives tools and knows how the work should be done. Both are discovered from their
manifests, so nothing anywhere holds a hardcoded list.

```
python scripts/list-tools.py                    # what exists, and whether it is ready
python scripts/run-tool.py procesio --help      # every action and its arguments
python scripts/run-agent.py procesio guidance   # the build-and-test playbook
```

The capability router at the bottom of this file maps a request to the command that
serves it. It is generated from the manifests, so trust it over your memory of an
earlier session.

## The contract

1. **JSON in, JSON out.** A tool prints exactly one JSON object on stdout for success,
   or `{"error": {"code", "message", "details"}}` for failure, and exits non-zero on
   failure. Progress and debug output go to stderr only. Never print anything else to
   stdout: a caller is parsing it.
2. **The manifest is the source of truth.** `tool.yaml` declares actions, arguments,
   secrets and output. The registry reads manifests; everything else reads the
   registry. Change the manifest in the same commit as the contract it describes.
3. **Regenerate what is generated.** After a manifest change run
   `python scripts/build-tool-skill.py <tool>` and `python scripts/build-router.py`.
   A stale generated file is worse than a missing one, because it will be believed.
4. **No secrets in files.** Ever. Credentials live in the OS credential store under
   `agents-and-tools:<tool>:<secret>` and are read through `tools/_lib/creds.py`.
   `python scripts/secret_scan.py` enforces this over the tree and refuses anything
   credential-shaped. Never log, print or commit a secret value.
5. **Framework and user data are separate.** `tools/`, `agents/` and `scripts/` are
   shareable code and carry zero user-specific data. Everything about a particular
   user or installation, including the environment registry and credential profiles,
   lives under `context-state-knowledge/`, which is never versioned. Resolve those
   paths through `tools/_lib/userdata.py`, never by hand.

## Credentials

Which store is used follows the platform, with no configuration: Windows Credential
Manager, the macOS login Keychain, or the Linux desktop keyring. A headless machine
has no OS keyring, so choose one explicitly with `AAT_CREDS_BACKEND`:
`encrypted-file` (read/write, passphrase in `AAT_SECRETS_PASSPHRASE`), or `file` / `env`
for secrets a host or cluster already manages. See `tools/_lib/README.md`.

Store a credential with `python scripts/set-credential.py <tool> <secret>`. Never write
one into a file, an argument, or a config, and never echo one back to the user.

## Working on a PROCESIO process

`tools/procesio/` holds the mechanics: the API client, the DTOs, the flow model, the
canvas layout engine, and one handler per action. Its long-form notes
(`PROCESIO-*-NOTES.md`) record non-obvious platform behaviour discovered the hard way,
and they are the first place to look when the API does something surprising.

`agents/procesio/` holds the method: the build-and-test playbook, the best practices,
and the verify gate. Before building or changing a process, read
`python scripts/run-agent.py procesio guidance`. Before calling one done, run
`python scripts/run-agent.py procesio verify --process-id <id>` - a process that
validates is not the same as a process that runs.

## Adding a tool

1. Create `tools/<name>/` with a `tool.yaml`, an entrypoint, and a `README.md`.
2. Declare every secret under `secrets:`. The registry reports `missing_secrets` until
   they are stored, which is how "not configured" stays distinct from "broken".
3. Generate its manual: `python scripts/build-tool-skill.py <name>`.
4. Confirm it appears in `python scripts/list-tools.py`.

Write anything you learn about an external system into a durable note in that tool's
own folder in the same session you learn it. A discovery that lives only in a chat is
gone by the next one.
